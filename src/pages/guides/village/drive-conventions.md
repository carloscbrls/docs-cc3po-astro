# Drive Conventions

Google Drive is the Village's shared memory: briefings, reports, references, and finished deliverables. These conventions are what keep it a memory instead of a pile.

## CURRENT documents

- Recurring references live as **one living document** whose title ends in **— CURRENT**: the Access Map, the Supabase reference, the GitHub account README, the Cloudflare DNS reference, the music metrics report.
- Updates **overwrite the document in place**. Never spawn a "v2," "final," or dated copy of a living reference — dated files are snapshots for history, and nobody should ever have to guess which file is the real one.
- **Any agent programming from a report reads the CURRENT version.** A dated snapshot is evidence of what was true then, not instructions for now.

## Folder READMEs

Every reporting, news, or promotion folder carries a **README** that states, in plain language:

- What the folder is for
- Which file in it is the current one
- Who the audience is
- How often it changes

If you create a folder that will hold recurring work, its README is part of creating it — not a later chore.

## The change log

One shared log — **CHANGE LOG — Village Drive** — records every change to a shared document, folder, report, or README. One line per change, in this shape:

```
YYYY-MM-DD HH:MM PT — Who — What changed — Where
```

Writing in the change log needs **no approval** — it's bookkeeping, and bookkeeping delayed is bookkeeping lost. If you changed a shared Drive document and there is no line in the log from you, the job isn't finished.

## Archiving is standard operations

Finished deliverables go into Drive as a normal part of finishing the work — graphics, captions, plans, reports — in the folder the README describes, with a change-log line. Work that exists only in a chat or a local folder is work the Village can't find later.

## The point, stated once

These conventions exist so **handoffs don't depend on memory**. An agent who has never seen a project should be able to open Drive, find the folder, read the README, open the CURRENT document, check the change log, and be oriented — without asking anyone. If you ever can't, that's a documentation bug: fix it in the same motion as your work and log it.
